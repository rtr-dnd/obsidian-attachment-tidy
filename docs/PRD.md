# Attachment Tidy PRD

## 背景・課題

Obsidianでは添付ファイルの保存先が既定でvaultルートなので、貼り付けた画像（`Pasted image *.png`）がルートに溜まっていく。どのノートで使っている画像なのかがファイルの場所からわからず、使われなくなった画像も残り続ける。ノートを別のフォルダへ移したときも、画像は元の場所に残ってしまう。

## 解決策

1回の操作で添付ファイルを整理するObsidianプラグイン。

- 使われている添付ファイル → 参照しているノートと同じフォルダへ移動
- 使われていない添付ファイル → 削除（ゴミ箱へ）

最初の用途はルートの整理だが、vault全体の「置き場所がずれた添付ファイル」も同じロジックで直せるように設計する。

## 用語

- **添付ファイル**: 対象拡張子に当てはまる、ノート（`.md`）・canvas（`.canvas`）以外のファイル
- **参照元**: その添付ファイルにリンクしているノートまたはcanvas
- **置き場所が正しい**: 添付ファイルが、参照元のいずれかと同じフォルダにある状態
- **スコープ**: 整理の対象にする添付ファイルの範囲。`root`（vaultルート直下のみ）か `vault`（全体）

## 振り分けルール

対象スコープ内の添付ファイルそれぞれについて、次のように判定する。

| 状態 | 処理 |
|---|---|
| 参照元が0件 | **削除** |
| 参照元のいずれかと同じフォルダにある | **何もしない** |
| それ以外 | 参照元のうち **最初の1件** のフォルダへ **移動** |

- 「最初の1件」は、参照元のパスを文字列順に並べたときの先頭とする（実行するたびに結果が変わらないように）。
- 移動先に同名のファイルがすでにある場合は、**スキップ** して結果で報告する（リネームはしない）。
- `vault` スコープで「何もしない」ルールがあるので、複数のフォルダから参照されている画像が実行のたびに行き来することはない。

## 機能

### コマンド・UI

- コマンド「Tidy root attachments」（スコープ `root`）
- コマンド「Tidy all attachments」（スコープ `vault`）
- リボンアイコン: 設定で選んだスコープで実行する（初期値は `root`）

### 処理フロー

1. スコープ内の添付ファイルを集める（除外フォルダにあるものは対象外）
2. 参照元を調べる
   - ノート: `app.metadataCache.resolvedLinks` を逆引きする
   - canvas: `.canvas` のJSONを読み、`type: "file"` のノードの `file` を見る
3. 上の振り分けルールで「移動・削除・スキップ」の計画を作る
4. 計画に **削除が含まれ、かつ設定「削除前に確認する」がON** のときだけ、確認モーダルを出す
   - 削除される一覧と、移動の件数を表示する
   - キャンセルした場合は何もしない（移動も行わない）
5. 実行する
   - 移動: `app.fileManager.renameFile()`（Obsidianがリンクを自動で更新する）
   - 削除: `app.vault.trash(file, system)`。システムのゴミ箱か `.trash` かは設定で選ぶ
6. 結果をNoticeで表示する（例: 「移動 16 / 削除 2 / スキップ 0」）。スキップがあれば理由も出す

### 設定

| 項目 | 初期値 |
|---|---|
| 対象拡張子 | `png, jpg, jpeg, gif, webp, svg` |
| 削除前に確認する | ON |
| 削除先 | システムのゴミ箱（`.trash` も選べる） |
| リボンのスコープ | `root` |
| 除外フォルダ | 空（1行に1フォルダ） |

## スコープ

- 上記のコマンド・リボン・確認モーダル・設定画面
- 振り分けルールを純粋関数（Obsidian APIに依存しない）として実装し、ユニットテストを書く

## 非スコープ

- 起動時やファイル変更時の自動実行
- 同名ファイルがあるときの自動リネーム
- ノートとcanvas以外（HTML、スライドのソースなど）からの参照の検出。これらは除外フォルダで対応する
- 添付ファイル用サブフォルダ（例: `./attachments/`）への振り分け

## 技術スタック・制約

- TypeScript + esbuild（Obsidian公式 sample plugin の構成に準拠）
- テスト: vitest（振り分けロジックのみ）
- 対象: Obsidianデスクトップ版（モバイルでも動くようにはするが、検証はデスクトップのみ）

## リスク

- ノート・canvas以外からしか参照されていないファイルは「未使用」と判定されて削除される。ゴミ箱に送ること、確認モーダルを出すこと、除外フォルダを設定できることで緩和する。
